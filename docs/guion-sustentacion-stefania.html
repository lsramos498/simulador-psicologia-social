1. Texto para leer en la sustentación (aprox. 2 a 3 minutos)

Buenos días. Mi nombre es Stefanía Díaz y en el proyecto Lumina me encargué del módulo de casos académicos y rúbricas del Backend. Mis requisitos fueron el RF-05 al RF-09 y la parte correspondiente del RF-17. El patrón de diseño que apliqué y debo sustentar es Builder.

Empecé desde cero en la rama stefania. Primero integré la base de la API del equipo y dejé una consulta inicial de casos con pruebas. Después aporté el esquema MySQL del modelo relacional de casos situacionales. Con eso pasamos de no tener módulo a tener una primera base funcional.

Para el avance del cuarenta por ciento implementé la persistencia real en MySQL: casos, escenas, preguntas, opciones, explicaciones y rúbricas. Agregué validaciones de estructura, las reglas de publicación y la creación del caso con el docente autenticado. También escribí y amplié pruebas unitarias para demostrar que el módulo no solo compilaba, sino que cumplía reglas de negocio.

Entre el cuarenta y el setenta por ciento fortalecí e integré el módulo. Implementé el Builder para construir el caso por pasos: creador, título, contexto, personajes, escenas, preguntas, opciones y rúbrica. El método build valida la estructura, pero no guarda en la base de datos; eso lo hace el servicio a través del repositorio. Separé claramente construir, validar y publicar. Publicar solo ocurre si el caso tiene escenas, preguntas, al menos dos opciones, una opción esperada, explicaciones y rúbrica. Si está incompleto, se rechaza con error de validación y no cambia de estado.

También implementé la edición de contenido en borrador con endpoints PATCH para escenas, preguntas y opciones, porque un caso no solo se crea: el docente debe poder corregirlo. Restringí la gestión para que solo el docente creador o un administrador puedan editar, publicar o archivar; si otro docente lo intenta, responde 403. Además, el estudiante autenticado no ve la opción correcta ni la explicación. Documenté la arquitectura, revisé antipatrones, aporté mi bloque del plan de pruebas PT-DCP-01 y dejé evidencia en commits, pull requests y pruebas automatizadas. Todo ese trabajo quedó integrado en develop.

En resumen, desde el uno por ciento hasta el setenta por ciento construí el módulo de casos de Lumina: consulta inicial, esquema y persistencia MySQL, Builder, validación, publicación, rúbricas, permisos de propietario, edición, pruebas y documentación. Puedo demostrarlo abriendo caso.builder.js, el método publicar del servicio y ejecutando las pruebas del módulo.
